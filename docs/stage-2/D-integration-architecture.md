# D. Integration architecture

## Verified deployment design

Cloudflare uses Vinext with the Vite Cloudflare plugin, React 19 and a pinned pnpm lockfile. B's `wrangler.student.jsonc` points to `worker/index.ts`, binds `ASSETS`, requires `run_worker_first: true` and disables preview URLs and `workers.dev` in the source configuration. After student JWT verification, the worker serves `/_next/static/` GET/HEAD through `env.ASSETS` and uses Vinext for other allowed paths. The built configuration resolves browser assets to `dist/client`. The server's similarly named modules under `dist/server` are imports. The build assertion checks scripts, CSS, catalog, PDF worker and source PDFs. [worker/index.ts](https://github.com/icebeluga/ChemAtlas/blob/63fd7e4b5287d74f66227742e8b2a4f47e37920f/worker/index.ts) · [vite.config.ts](https://github.com/icebeluga/ChemAtlas/blob/63fd7e4b5287d74f66227742e8b2a4f47e37920f/vite.config.ts) · [scripts/assert-student-private-config.mjs](https://github.com/icebeluga/ChemAtlas/blob/63fd7e4b5287d74f66227742e8b2a4f47e37920f/scripts/assert-student-private-config.mjs)

Student authentication verifies the Access JWT against team keys, configured audience, time window and a valid identity. Cloudflare Access policies own the allowed email population. Binding names include `CF_ACCESS_TEAM_DOMAIN` and `CHEMATLAS_STUDENT_ACCESS_AUD`. The student blocks admin/review paths before serving assets, has no private review bindings and uses private cache behavior. The independent private Worker has separate Access configuration and D1/R2 storage. Preserve its deployment, migrations, owner checks and immutable crop revisions. Hosted records and current credentials remain outside the audit. [lib/student-access.mjs](https://github.com/icebeluga/ChemAtlas/blob/63fd7e4b5287d74f66227742e8b2a4f47e37920f/lib/student-access.mjs) · [wrangler.private-review.jsonc](https://github.com/icebeluga/ChemAtlas/blob/63fd7e4b5287d74f66227742e8b2a4f47e37920f/wrangler.private-review.jsonc)

## Conflict-resolution strategy

| Surface | Decision |
| --- | --- |
| Worker entry, Vinext/Vite, package and lockfile | Start at B. Preserve the protected entry, generated config and asset checks. Add only dependencies required by the selected UI with a regenerated lockfile if needed. |
| `app/page.tsx`, `app/globals.css` | Bring C in as an exact two-file baseline. Split or scope A's workspace styling to avoid affecting admin rules and newer state/navigation. Preserve validated query/URL contracts. |
| `app/practice-builder/page.tsx`, A builder components and `lib/worksheet*.ts` | Port the A route, draft/schema and export stack. Reconcile name collisions with B's `lib/worksheet.mjs` using explicit imports and a shared-context adapter. |
| `public/questions.json`, registries and `research/stimuli.json` | Build the reviewed candidate separately. Publish matching question/worksheet manifests and keep the B group registry. |
| Sites connector/auth and Cloudflare auth | Keep Cloudflare authentication authoritative. Prove selected student features work with the Cloudflare adapter before dropping any Sites hooks. |
| Private review and accepted images | Retain dashboard and storage in the independent private service. In the student build use the PDF path unless a read-only accepted-only interface is approved and tested. Scope any future delivery to immutable accepted assets, student Access, and explicit authorization. |

The integration should remain one repository with two independently deployed applications. Preserve a private-data boundary in builds and at request time. Test that admin pages, draft crops, backup/import APIs and storage bindings are inaccessible from the student service. The pinned release build log lists a review-dashboard module in the server upload. Inspect the generated client asset manifest and route bundles as well as endpoint guards before declaring build-level isolation.

## Version-control safeguards for Stage 5

- **Observed:** archive, reconstructed UI, crop/review branches, manual release support and protected application pin diverged. The prior integration explicitly reconciled selected files, leaving Sites-only functionality and the larger catalog absent. An interrupted workspace left diagnostics and local refinements unverified. **Unknown:** the cause of any specific missing Sites draft.
- Record immutable development and approved-release SHAs separately. Require an approved release manifest containing Git SHA, GitHub workflow SHA, catalog Git hash and digest, PDF manifest, generated asset manifest and Cloudflare version/rollback IDs.
- Store reviewed changes and test evidence in small pushed checkpoints. Freeze exact Sites exports after milestone changes with path/mode/blob inventories and explicit exclusions. Audit branch comparisons before taking the newest branch as complete.
- Require CI and a reproducible desktop/mobile screenshot set for releases. Tie the checks to the exact candidate commit and catalog. Track catalog migration decisions and staged rollback manifests independently from interface changes.
- Archive and periodically test recovery of the approved application artifacts. Test private backup restore capacity with synthetic or approved isolated snapshots, and separate private restore from student application rollback.
