# GitHub governance

GitHub's branch response showed `main` as unprotected and status-check enforcement off. The branch protection endpoint returned 403 for the integration. The rulesets endpoint returned 403 and indicated that this private repository requires GitHub Pro to use rulesets. The connector could create and push the isolated release branch. Repository governance still requires owner action.

1. Keep the repository private. With a compatible GitHub plan, open **Settings → Rules → Rulesets → New branch ruleset** or **Settings → Branches → Add branch protection rule**. Target `main`, activate the rule, block force pushes and deletion, and require a pull request. Require at least one approval when a second eligible reviewer is available. Enable dismissal of stale approvals after new pushes and required conversation resolution. Apply the rule to administrators as well where supported.
2. After a PR has emitted the check, require **Validate student release (no deploy) (candidate)** from GitHub Actions, using the exact check name GitHub shows. Require the branch to be up to date before merge. Protect the archived Sites ref against rewriting and deletion with a separate ruleset where supported.
3. Under **Settings → Environments**, create `chematlas-student-production` and restrict deployments to `main`. On plans that support required reviewers for private repos, require an authorized reviewer, prevent self-review and disable admin bypass when feasible. Store the approval digest and Cloudflare credentials in that environment. Restrict credential use to the guarded student promotion and retire the old release credentials or workflow at cutover with owner authorization. If environment secrets are unavailable, keep the proposed automation inactive and use an explicitly authorized, audited promotion from an owner-controlled environment with the same exact-artifact checks. If required reviewers are unavailable, the owner digest and explicit dispatch are the independent approval controls.
4. Verify the rule and environment after saving. Confirm a test PR cannot merge before its check and required reviews. Record any unavailable protections in the release log. Until then, enforce the PR, passing check and release approval through owner review.
